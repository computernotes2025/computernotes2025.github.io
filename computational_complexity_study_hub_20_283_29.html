Important Definitions

Exam-ready definitions based on the supplied reference notes.

Computational Complexity

The branch of theory of computation in computer science that investigates the resources required for the execution of an algorithm as a function of problem size.

Time Complexity

It quantifies the amount of time taken by an algorithm to run as a function of the length of the input.

Space Complexity

It quantifies the amount of space or memory taken by an algorithm to run as a function of the length of the input.

Complexity

It is the measurement or growth rate of an algorithm with respect to time and space.

Big O Notation

Big O describes an asymptotic upper bound on how an algorithm's time or space requirement grows as input size increases. It is commonly used to express worst-case time, but Big O and worst case are not the same thing.

Best Case

The minimum number of operations executed for an input of a given size; it describes behaviour under optimal conditions.

Worst Case

The maximum number of operations executed for an input of a given size.

Average Case

It considers the possible inputs and the computing time for those inputs.

Dominant Term

The term that grows fastest and determines the overall growth rate for sufficiently large input sizes. Example: in n² + 3n + 5, n² is dominant.

Constant Factor

A fixed multiplier in a running-time expression. In asymptotic analysis, constant multipliers are ignored when expressing the growth class.

Big O — Upper Bound

Shows that the growth rate will not exceed a stated order, apart from constant factors, for sufficiently large inputs. It is often used when reporting worst-case complexity.

Big Omega — Lower Bound

Shows that the growth rate is at least a stated order, apart from constant factors, for sufficiently large inputs.

Big Theta — Tight Bound

Shows that the growth rate is both upper-bounded and lower-bounded by the same order, apart from constant factors.

Binary Search Derivation

After k halvings, the remaining size is n / 2ᵏ. When it reaches 1: n / 2ᵏ = 1, so k = log₂ n.

Remember: Best, average and worst case describe input situations. O, Ω and Θ describe mathematical bounds. They are related ideas, but they are not interchangeable definitions.

Best Case, Average Case and Worst Case

These describe how much work an algorithm performs for different inputs of the same size.

Minimum work

Best Case

The minimum number of operations an algorithm performs for any input of size n.

Example: In linear search, the required value is at the first position. Only one comparison is needed.

O(1)
Typical expected work

Average Case

The expected number of operations over the possible inputs of size n, using an assumed probability distribution for those inputs.

Example: In linear search, assume the value is equally likely to be at any position. On average, about (n + 1) / 2 comparisons are needed.

O(n)
Maximum work

Worst Case

The maximum number of operations an algorithm may perform for an input of size n.

Example: In linear search, the value is at the last position or is not present. Up to n comparisons are needed.

O(n)

One algorithm, three cases: Linear Search

Suppose an array contains n elements and we search for one value from left to right.

CaseExample input situationNumber of comparisonsGrowth
BestValue is the first element1O(1)
AverageValue is equally likely to be in any position(n + 1) / 2 on averageO(n)
WorstValue is last, or is absentnO(n)
Why is the average case O(n)?
For equally likely positions, the average comparisons are:
[1 + 2 + 3 + … + n] / n = (n + 1) / 2
When n becomes large, this grows in direct proportion to n. Therefore, the average-case growth is linear: O(n).
Important distinction: Best, average and worst case describe the input situation and the amount of work. Big O, Big Omega and Big Theta describe mathematical bounds. For example, we can say “the worst-case time complexity of linear search is O(n)”. Do not define Big O itself as “worst case”.

Another example: Bubble Sort

CaseSituationTime complexity
BestArray is already sorted and the algorithm uses a swap/check flag to stop earlyO(n)

Note: The O(n) best case applies to the optimised Bubble Sort that stops when a pass makes no swaps. A basic version that always completes every pass takes O(n²), even for an already sorted array.

How to Analyse Code

Count repetitions, multiply nested loop limits, and add separate sections.

1. Single loop

for (int k = 0; k < n; k++)
{
    s += k;
}

The statement executes n times. Complexity: O(n)

2. Nested loops

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < m; j++)
    {
        // constant-time statement
    }
}

Inner statement executes n × m times. Complexity: O(nm)

3. Separate loops

for (int i = 0; i < n; i++)
    statement;

for (int j = 0; j < m; j++)
    statement;

Total work is n + m. Complexity: O(n + m)

4. Nested loops followed by a separate loop

Example code:

for (int i = 0; i < n; i++)
{
    for (int j = 0; j < m; j++)
    {
        System.out.println(i + " " + j);
    }
}

for (int k = 0; k < x; k++)
{
    System.out.println(k);
}

Step 1 – Analyse the nested loops: The outer loop runs n times. For every outer iteration, the inner loop runs m times. Therefore, the print statement executes n × m times.

Step 2 – Analyse the separate loop: The last loop runs x times, so its statement executes x times.

Step 3 – Add the work: These loops run one after another, so their execution counts are added.

O(n × m + x)
Numerical example: Let n = 3, m = 4 and x = 5.
Nested loops: 3 × 4 = 12 executions.
Separate loop: 5 executions.
Total = 12 + 5 = 17 executions.

If all limits are N: The expression becomes N × N + N = N² + N. Since N² grows faster than N, the lower-order term N is ignored.

O(N² + N) = O(N²)
Shortcut: Sequential sections are added. Nested loop limits are multiplied. Ignore constant factors and lower-order terms in the final Big O expression.

ISC Previous-Year Questions with Answers

ISC 2010 – Worst-case complexity of two separate loops

Question: What is the worst-case complexity of the following code segment? How would the complexity change if the second loop went to N instead of M?

for (int i = 0; i < N; i++)
{
    sequence of statements;
}
for (int j = 0; j < M; j++)
{
    sequence of statements;
}

Answer: The first loop executes N times and the second loop executes M times. Since the loops are separate, their complexities are added.

O(N + M)

If the second loop also runs N times, the total is O(N + N) = O(2N) = O(N).

ISC 2011 – Big O notation

Question: What is Big O notation?

Answer: Big O notation describes the asymptotic upper bound of an algorithm's growth rate as the input size increases. It is commonly used to express an algorithm's worst-case time complexity.

ISC 2015 – Computational complexity and a single loop

Question: Define computational complexity. Calculate the complexity using Big O notation for the following code segment.

for (int k = 0; k < n; k++)
    s += k;

Answer: Computational complexity is the measure of the resources required by an algorithm as a function of the problem size. The loop executes n times and performs a constant amount of work in each iteration.

O(n)

ISC 2015 – Nested triangular loop (MCQ)

Question: Find the worst-case complexity of the following code segment.

for (int i = 1; i <= n; i++)
{
    for (int j = 1; j <= i; j++)
    {
        statement;
    }
}

Answer: The inner loop executes 1 time for i = 1, 2 times for i = 2, and so on, up to n times. Total executions = 1 + 2 + 3 + ... + n = n(n + 1)/2.

O(n²)

Correct MCQ option: O(n²).

ISC 2017 – Separate loop followed by a nested loop

Question: (i) What is the worst-case complexity of the following code segment? (ii) How would the complexity change if all the three loops went to N instead of a, b and c?

for (int x = 1; x <= a; x++)
{
    statements;
}
for (int y = 1; y <= b; y++)
{
    for (int z = 1; z <= c; z++)
    {
        statements;
    }
}

Answer (i): The first loop executes a times. The nested loops execute b × c times. Since the first loop and the nested-loop block are sequential, add their complexities.

O(a + bc)

Answer (ii): If a = b = c = N, then O(N + N²). The dominant term is N².

O(N²)

ISC 2018 – Big O notation and factors determining complexity

Question: Define Big O notation. State the two factors which determine the complexity of an algorithm.

Answer: Big O notation expresses the asymptotic upper bound on the growth of an algorithm with respect to input size. The two factors are:

  1. Time complexity: the time or number of basic operations required.
  2. Space complexity: the memory required during execution.
ISC 2019 – Compare O(n²) and O(2n)

Question: Compare the two complexities O(n²) and O(2n) and state which is better and why.

Answer: Taking O(2n) literally, it simplifies to O(n), because constant factors are ignored. O(n) grows linearly, whereas O(n²) grows quadratically. Therefore, O(2n), i.e. O(n), is better because it grows more slowly as n increases.

Notation note: The typed expression in the question is O(2n), not O(2ⁿ). If the original paper intended 2 raised to n, the comparison and answer would be different.
Additional scanned question – Three loops with P and Q

Question: Write Big O notation for the worst-case complexity of the following code segment.

for (int i = 1; i <= P; i++)
{
    statements;
    for (int j = 1; j <= P; j++)
    {
        for (int k = 1; k <= Q; k++)
        {
            statements;
        }
    }
}

Answer: The outer loop executes P times. The inner two loops execute P × Q times for each outer iteration, giving P × P × Q = P²Q. The standalone statement inside the outer loop executes P times, which does not change the dominant term.

O(P²Q)

Exam reminder: Sequential loops → add their counts. Nested loops → multiply their counts. For a sum of terms, retain the term that grows fastest.

Quick Revision Sheet

A compact last-minute recap.

Growth order

O(1) → O(log n) → O(n) → O(n²)

For large n, each step to the right generally grows faster.

Dominant Term

For 4n² + 7n + 12, the dominant term is n² because it grows faster than n and the constant 12. Therefore, the complexity is O(n²).

Constant Factors

For 5n + 20, ignore the fixed multiplier 5 and constant 20 when expressing Big O. The complexity is O(n).

Loop rules

One loop: O(n). Two nested n-loops: O(n²). Separate n and m loops: O(n + m). Nested n and m loops: O(nm).

Best / worst linear search

Best: first element matches → O(1). Worst: last element or absent → O(n).

Bubble sort

Worst case: O(n²). Best case: O(n) when an already-sorted check allows early termination.

Remember these points

  • Time complexity measures running time in relation to input length.
  • Space complexity measures memory in relation to input length.
  • Best case = minimum work; average case = expected work over possible inputs; worst case = maximum work.
  • Big O is an upper-bound notation; Ω is a lower-bound notation; Θ is a tight-bound notation.
  • Ignore constants and lower-order terms when simplifying asymptotic expressions.
  • Binary search requires sorted data and repeatedly halves the search range.
